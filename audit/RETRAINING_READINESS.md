## Data correction and current protocol

The prior `Data/TvsN/GSE45498_NvT.csv` must not be used for model evaluation. Its 183 expression profiles all match NCBI's official GSE45498 supplementary matrix, but matching those profiles to the GPL16299 Series Matrix reveals 52 incorrect stored labels and duplicated sample names that assign some profiles to the wrong patient. This invalidates all held-out results made with that target, including the seed-43 through seed-45 runs. They remain in `results/` for audit history only and must not be cited as performance evidence.

[`rebuild_gse45498_tvsn.py`](rebuild_gse45498_tvsn.py) reconstructs the target from the downloaded official NCBI files. It matches each expression profile to its GEO accession/title, derives labels and numeric patient IDs from GEO metadata, and excludes metastatic specimens. Its output, `Data/TvsN/GSE45498_TvsN_official_200.csv`, contains 236 genes, 160 Tumor and 40 Normal samples from 158 patient groups. The sample-level provenance, source URLs and hashes are in [gse45498_tvsn_rebuild_manifest.json](gse45498_tvsn_rebuild_manifest.json). A new [GSE41970/GSE45498 mRNA crosswalk](gse41970_mrna_crosswalk.json) confirms both accessions contain identical mRNA supplements and sample metadata. The 224-sample count in the original article refers to the 165-tumor/59-normal miRNA analysis; its mRNA analysis reports 158 tumors, 40 normals and 54 metastases. The available public GPL16299 matrix has 160 tumors, 40 normals and 54 metastases, so the usable mRNA TvsN subset is 200—not 224. The exact two primary tumor samples excluded from the article's mRNA analysis are not identified in GEO metadata; do not guess which to remove. The second GEO supplement contains only `nmiR` microRNA features, as documented in [gse45498_raw_data_audit.json](gse45498_raw_data_audit.json), and cannot resolve the two-sample difference. The corrected local file is the most complete reproducible public mRNA target available, with the remaining two-case source-publication mismatch clearly bounded.

The experiment runner and readiness validator now default to `TCGA_BRCA_NvT_new.csv`, excluding its two `Unknown` sample-type-06 rows, and the reconstructed GEO target. This changes the prior source-feature count by one while leaving the target/shared counts unchanged. The source candidate is closer to the paper's 592 samples; its inclusion/provenance policy still needs to be recorded.

This preserves the manuscript trace objective and full empirical MMD²; the detached `final_objective_device_smoke` completed with exit code 0, and its regression checks confirmed matching cached/uncached objective values and target-coordinate gradients, plus matching CPU/MPS loss histories. These are computational optimizations only: they do not alter classifier predictions or establish a performance gain. Large dense target kernels still require substantial memory.

The differentiable KPCA-DA optimizer now accepts `--kpca-optimization-device {auto,cpu,cuda,mps}`. The experiment runner defaults to `auto` (CUDA, then Apple MPS, then CPU); standalone API calls retain CPU as their default. Effective device is saved in every run artifact and included in pair matching and cross-seed aggregation so device changes cannot be silently pooled. The detached `final_objective_device_smoke` passed, including a full synthetic fit whose CPU/MPS coordinates differed by at most `2.98e-8`, with matching final objective and loss history. The same smoke verifies that paired comparisons reject different effective devices. A local 5,000-gene dense matrix multiplication microbenchmark measured 3.2 ms on CPU and 1.4 ms on MPS per operation. This supports using MPS for runtime, not a classifier-accuracy claim; full-cohort memory and throughput remain to be measured.

The zero-step `baseline` KPCA-map control now uses effective regularization mode `none`. It previously constructed and reported a trace penalty despite taking no optimizer step, needlessly allocating the dense target-gene kernel. The adapted arm still uses the configured manuscript trace objective. This control now accurately represents no adaptation and avoids that matrix allocation; comparison artifacts report its effective and requested modes separately.

The nested `pyDeepInsightv3.image_transformer_new` package had a broken fallback import path (`Scripts/examples/Scripts`), so importing it as `Scripts.pyDeepInsightv3...` from the repository root could fail unless `Scripts` was already on `PYTHONPATH`. The fallback now adds the actual parent `Scripts` directory. An isolated package-import check from the repository root passed without pre-adding that directory.

The lambda-tuning cache now includes all fit-affecting optimizer settings in its signature. Before this, changing a model's learning rate, regularizer, bandwidth, epoch count or device after tuning could return stale coordinates. The detached `tuned_cache_invalidation_smoke` passed with exit code 0, including a CPU-to-MPS change after tuning that verifies the new fit uses the selected device.

For development runs without target-test labels, `load_expression_dataset(..., include_labels=False)` now skips the final label row in the CSV parser itself. The corrected GEO matrix check confirmed exact equality of expression values, gene order and sample IDs against the labeled loader, with no returned label array; the full smoke now asserts that the parser receives `skipfooter=1`.

The public image-transformer constructor no longer overrides `KPCA_DA` with its old 100-step/0.0001-learning-rate/0.1-lambda defaults. It delegates to the shared core defaults and uses the canonical 227×227 input size unless callers explicitly override parameters. This removes a discrepancy between direct library use and the paper-aligned experiment runner; no performance result is inferred from the default change.

Two additional paired results are now available. The seed-48 shared-pixel anchor forced all 222 shared genes to identical pixels and raised balanced accuracy from 0.458 to 0.500 (conditional patient-bootstrap interval for ΔBA 0.010–0.083), but Normal sensitivity remained 0 and the score gain came only from Tumor sensitivity rising 0.917→1.000. This geometry fix therefore improves exact correspondence but does not resolve the class collapse. On seed 51, the ranked-filter raw DeepInsight baseline scored 0.669 BA and 0.690 macro-F1, while KPCA-DA scored 0.500 and 0.453; Normal sensitivity fell 0.400→0.000 while Tumor sensitivity rose 0.938→1.000. The conditional ΔBA interval was −0.354 to −0.008. Treat this as a development warning that the current adaptation can harm the paper-style baseline on this split; it does not justify tuning on the same held-out labels. The paired artifacts and settings remain the source of truth for further investigation.

# Proposed corrections to the paper and supplement

This is an author-editing sheet for the two supplied PDFs. It does not alter or replace either PDF. Recommendations distinguish mathematical corrections from results that need new experiments. Do not copy development-run metrics into the manuscript as final claims.

## Corrections required for mathematical consistency

| Location | Verified inconsistency | Proposed manuscript change |
|---|---|---|
| Main pp. 12–13, Eqs. 7–8 | The displayed `V Λ^(-1/2)` is described as the reduced sample representation, while the implementation's `KernelPCA.fit_transform` returns training scores equivalent to `V Λ^(1/2)`. The inverse-square-root form corresponds to normalized kernel expansion coefficients under the stated convention. | Separate and name the two quantities. Use `Z = V Λ^(1/2)` for the training score coordinates used by the code, and reserve `A = V Λ^(-1/2)` for expansion coefficients. State the eigenvector normalization convention. The implementation check is in [`current_smoke_results.json`](../audit/current_smoke_results.json). |
| Main p. 13, Eq. 15; Supplement Note 2, N2E2 | The main text defines empirical squared MMD with source, target, and cross-kernel means. N2E2/code at the audited revision used `abs(mean(K_tt) - 2 mean(K_st))`, which can assign a lower loss to unequal distributions. Current core code implements the main-text empirical MMD². | Make N2E2 identical to the declared main-text estimator: `mean(K_ss) + mean(K_tt) - 2 mean(K_st)`, with the estimator convention and diagonal treatment stated. Remove the absolute value. Recompute all λ-search tables and downstream figures from one final optimizer endpoint. |
| Main p. 14, Eqs. 17–22; Supplement Note 2 | The positive trace term is called variance preservation/maximization. Minimizing `trace(Z_tᵀ K_t Z_t)` instead penalizes embedding magnitude for a positive-semidefinite kernel; it does not constrain movement from the initial embedding or guarantee variance preservation. | If retaining the current trace objective, rename it as a trace/embedding-energy penalty and remove the variance-preservation guarantee. If adopting normalized reference-coordinate preservation, replace the equation, name it as a method revision, and regenerate every result and ablation that uses the old term. The fingerprinted fresh-split seed-54 reference-penalty comparison reduced BA by 0.177 (conditional patient-bootstrap 95% interval −0.250 to −0.104) and macro-F1 by 0.307 (−0.403 to −0.197), with Tumor sensitivity falling to zero; the seed-46 result was also inconclusive and collapsed Tumor sensitivity. Current evidence therefore does not support adopting reference preservation for performance. Keep the manuscript's trace equation as the faithful comparator, correct its interpretation, and treat any alternative regularizer as a new method requiring a principled derivation and independent replication. |
| Supplement Note 1, adaptive γ explanation | For fixed distance, `exp(-γ d²)` tends to one as γ decreases toward zero and tends to zero as γ increases. Also, `γ = 1 / median(d²)` gives `exp(-1) ≈ 0.368` at the median squared distance, not approximately 0.5. | Correct the direction of the bandwidth explanation and state the actual kernel value implied by the heuristic. Keep the current equation only if that is the intended heuristic; do not characterize it as a median-kernel-value 0.5 rule. |

## Tables and figures requiring recalculation or qualification

| Location | Evidence and risk | Proposed manuscript change |
|---|---|---|
| Supplement Tables S1–S3 | Table S3 is described as monotonically increasing in λ, but the γ=500 row decreases from 0.001675 to 0.001099 between its first two λ values. At γ=5000, λ=0.0001, Table S2 MMD is 0.003507 while Table S3 total loss is 0.000887. A total formed from MMD plus a nonnegative regularizer at the same endpoint cannot be lower than MMD. The old implementation also mixed pre-update total loss with post-update MMD. | Remove the monotonicity claim. Re-run all entries while recording MMD, regularizer, total loss, γ, λ, and final coordinates at the same endpoint. Replace the tables and selection narrative from those saved results. The current audit cannot establish the provenance of the published entries without original run artifacts. |
| Main Figure 3 and Table 3; Supplement Figure 1 | Figure 3's example values 2.0371 and 0.7010 imply a 65.6% decrease, not approximately 72%. The Table 3 means 2.086 and 0.584 imply approximately 72.0%. The legacy notebooks also applied post-hoc shifts before some reported distances. | Rebuild figures and values from saved, unshifted projections with one declared source-fitted projection and a named distance. Label example-run and across-run percentages separately. Do not retain a 72% example-run annotation unless recalculation supports it. The current paired seed-47 diagnostic reports mean marginal 1D W1 of 2.4249 (baseline) and 2.4328 (KPCA-DA), so it does not support an alignment improvement; see the [saved metrics](../audit/seed47_common_frame_ica_comparison.json) and [diagnostic plot](../audit/seed47_common_frame_ica_figure.png). This diagnostic is development evidence, not a replacement paper estimate. |
| Main Table 2 | The printed means ± spreads cover three task directions. The current corrected runner can screen the four objective components on TvsN, but the survival cohort/labels do not match the manuscript and the other directions are not yet validated. | Regenerate Table 2 only after the task cohorts, labels, and repeated-run protocol are verified. Until then, label the existing numbers as unverified against the supplied code/data; do not present a one-seed TvsN ablation as a reproduction of the three-direction table. |
| Main p. 15 baseline | The paper says the baseline applies DeepInsight directly to raw source/target data, but does not specify how its gene map is fitted or how source/target-private genes receive coordinates. The existing runner's zero-optimization baseline still fits KPCA maps, so it is only an optimizer ablation. | State the baseline feature intersection, source/target data used to fit the map, preprocessing statistics, and frozen-inference behavior. The new development arm uses source-training shared genes with a frozen t-SNE DeepInsight map; report it as an explicit implementation choice until the original baseline configuration is recovered, then regenerate the comparison with that declared baseline. |
| Main pp. 14–15, expression pixels and pretrained classifier | The runner defaults to source-fitted MinMax scaling; a separate, label-free target-adaptation-fitted shared-gene candidate is now implemented for controlled development comparison, preserves out-of-range target floats, repeats expression intensities across RGB, and applies ImageNet normalization. `ToTensor` leaves float input unchanged; the seed-51 preflight observed normalized target input above 115. The manuscript does not specify clipping or pretrained-weight normalization. | State the complete intensity-to-tensor transform, including whether out-of-range values are clipped and whether ImageNet-pretrained weights are used. Choose any transform policy using source validation and unlabeled target adaptation only, freeze it before scoring target test, and report its exact settings. The same-split seed-52 comparison using standard pretrained `resnet50` had the same BA (0.500) as the default `resnet50d` control but flipped predictions from all Normal to all Tumor; this is not evidence that the paper-named backbone improves balanced performance. Do not choose an architecture or intensity policy from this inspected held-out split. Do not imply clipping is part of the paper method unless the manuscript or original run artifacts support it. |
| Main pp. 7–10 and Supplement Note 4, attribution | Main text specifies target top-ten rankings; the supplement specifies thresholded training maps. These are different data partitions and selection rules. The saved-run analyzer now has separate `main_text_top_k` (held-out target rankings) and `supplement_threshold` (source-training maps, strict normalized mean-CAM >0.5) modes, each tied to its domain map and retained gene order. The main-text ranking uses a stable input-order tie policy and both outputs report pixel collisions. | Choose and consistently state the target population, class aggregation, normalization, ranking/threshold rule, and top-k. Regenerate rankings and external validation from the selected workflow. Do not combine top-ten target results with thresholded training results under one method description. |

## Cohort and evaluation claims requiring source data or new evidence

| Claim | Verified limitation | Required action before retaining the claim |
|---|---|---|
| GEO cohort size and labels | The original article reports 224 tumor/normal samples (165/59) for miRNA analysis and 158 tumor, 40 normal and 54 metastatic mRNA profiles. The identical public GSE41970/GSE45498 GPL16299 mRNA deposits contain 160 primary tumor profiles, 40 normal profiles and 54 metastatic profiles. A sample-level reconciliation now shows the 160 GEO tumor profiles map to 158 patient IDs: patients 91 and 101 each have two separately named tumor profiles; 40 patients also have both a normal and a tumor profile, which the patient-grouped split must keep together. This numerically matches the article's 158 count if it refers to patients, but the article does not explicitly establish that counting unit or explain these profiles, so exact inclusion/QC correspondence remains unverified. The 200-profile primary/normal file is the available public mRNA cohort, not the 224-sample miRNA cohort. The separate `GSE45498_raw_data.txt.gz` supplement is miRNA data (734 endogenous `nmiR` features) and cannot resolve any mRNA inclusion question. The prior local 183-sample file had 52 label discrepancies and identity errors. See the [GEO crosswalk audit](../audit/gse41970_mrna_crosswalk.json) and the sample-level [rebuild manifest](../audit/gse45498_tvsn_rebuild_manifest.json). | Correct any claim that treats 224 as the mRNA TvsN cohort. State the assay-specific profile counts (200 available public mRNA primary/normal profiles; GEO has 160 tumor profiles from 158 patient IDs, while the article reports 158 tumor profiles and 40 normals) and explain that the counting-unit reconciliation is plausible but not confirmed. Recover the authors' sample-level inclusion/QC manifest before claiming exact profile-level replication. Do not discard either GEO profile or invent exclusions based only on this numerical match, and do not substitute miRNA values for mRNA. |
| TCGA survival 154-sample 55/99 split | The legacy expression matrix has 154 columns but includes 37 non-primary-tumor specimens. The official TCGA-CDR mapping of 117 primary tumors gives 38 aggressive, 31 indolent, 41 intermediate and 7 missing under the paper's thresholds; this does not recover 55/99, and the stated BRCA DSS endpoint is approximated in TCGA-CDR. | Recover the original sample-to-label manifest and endpoint derivation. Do not use tumor/normal labels or a different survival endpoint as a substitute. If source records cannot be recovered, mark the survival result as unreproducible from the supplied materials and update the claims. |
| Statistical significance across tasks | Several corrected TvsN development pairs now have patient-level artifacts, but they do not reconstruct run-level scores for all six paper directions or the published means/spreads. Repeated patient splits can overlap and are not automatically independent patient-level observations. | Recover the original run-level paired scores and define the pairing unit and multiplicity procedure, or rerun a predeclared study with an appropriate independent unit. Do not infer the published p-values from current development runs. |
| CAN comparison | The checkout contains external CAN predictions but no training method, configuration, or checkpoint workflow. Main p. 15's description says the feature extractor is trained on target-train images, but the cited CAN method jointly uses labeled-source classification, target clustering/pseudo-label updates, and contrastive domain discrepancy ([original CAN paper](https://openaccess.thecvf.com/content_CVPR_2019/papers/Kang_Contrastive_Adaptation_Network_for_Unsupervised_Domain_Adaptation_CVPR_2019_paper.pdf)). The [authors' repository](https://github.com/kgl-prml/Contrastive-Adaptation-Network-for-Unsupervised-Domain-Adaptation) still does not contain the promised multi-source code. | Recover the exact implementation/configuration that generated the supplied CAN predictions and document the source/target losses, clustering schedule, sampling, backbone, image preprocessing and checkpoint selection. If that provenance is unavailable, describe CAN as an unreproduced external result rather than adding a guessed implementation to the benchmark. |
